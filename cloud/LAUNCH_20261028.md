## 无效尝试及修复

- PowerShell 子进程继承的模块路径导致加密模块无法加载；临时输入程序改用当前 `$PSHOME/Modules`，随后保存成功。读取加密字符串需去掉文件末尾换行。正式脚本本身不持久化用户输入。
- 旧脚本用 `2>&1` 捕获 Wrangler 警告，在 Windows PowerShell 的 Stop 策略下中止；改用现有 Run-Npm 直接执行并校验退出码。
- 新 Wrangler 首次 `pages project create` 默认转发为 Worker，错误创建了同名临时 Worker；已清理该临时 Worker，真正 Pages 和 `-api` Worker 保留。首次显式 `--force` 创建 Pages。
- `pages project list --json` 实测字段为 `Project Name`，兼容旧 `name`。
- Pages 不支持自定义 `--config` 路径；改为 `.wrangler/pages/wrangler.json` 并用 `--cwd` 选择目录。
- 本机 pages.dev 正常，但 workers.dev TLS 握手失败；改用官方 Service Binding 同域网关，随后真实联调成功。没有关闭证书验证。
