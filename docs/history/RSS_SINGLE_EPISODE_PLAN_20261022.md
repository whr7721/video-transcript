## 首版范围和入口

在现有导入弹窗提供“本地文件 / 播客RSS”。贴公开RSS → 解析预览 → 选一集 → 确认导入方式 → 显示获取/校验/转写进度 → 打开原稿、编辑、研究、笔记及导出。

预览显示节目、单集标题、日期、已知时长、文字可用情况。解析RSS只读取节目元数据，不取各集全文/音频、不调用模型。列表先显示20集，缓存内分页；初定最多500集并明确是否截断，不能宣称已获得全量节目。

首版只承诺公开RSS地址，不承诺任意小宇宙/Apple/Spotify分享链接；遇到网页给出“需要RSS地址”的可操作提示，不扫描网页绕路猜测。暂不做账号登录、付费订阅、私密token feed、自动追更、批量全选、订阅管理或OPML。

若有支持格式的podcast:transcript，提供“节目提供文字”导入；保留出处并标记完整性尚未人工核验，不把shownotes当全文。首版支持text/plain与WebVTT，其他格式提示尚不支持，可显式选择本地转写。失败不静默切换路径。

没有可用全文时，选中后下载音频并使用现有本地CPU识别。中文优先；音频仍限制1GB/两小时，多音轨规则不变。未知时长明确标记，实际媒体探测超限拒绝。文字导入独立限制2MB/20万字符，已知超两小时单集首版不接；没有音频/时间戳时不伪造回听和语音时间轴。

UI沿用现有阅读布局，实施时使用frontend-design、ui-ux-pro-max，发布前按web-design-guidelines检查；不另做一个播客客户端首页。

## 技术选型与复用

- 解析候选：feedparser。已核对官方pyproject为Python>=3.10、BSD-2-Clause，另有requests/feedparser-sgmllib依赖。实施先验证可安装的发布版本和锁定依赖，不直接用未发布main。使用本站受控HTTP获取字节，再传给解析器，不让parser任意联网。原始XML树解析仅作对照，不自行重写完整RSS/Atom兼容库。
- HTTP复用article_fetch的公开目标校验、逐跳DNS/IP约束和同源写入保护；现fetch会聚合字节且按文章设30秒，不能直接拿来内存下载1GB音频。提取共用的受控流式获取基础，文章原默认行为保留并回归。
- RSS初定解压后8MB上限、30秒总预算、最多5次跳转，XML复杂度有界并拒绝DTD/外部实体；实测既有feed为5.12MB，不能沿用文章3MB默认值。缓存解析快照和更新时间，用户显式刷新；不后台定时扫描。
- 音频下载共享现有受管暂存、实收字节计量、5GB预留和清理规则，再交同一媒体校验/ASR阶段。不能先下载到不计费目录再导入，也不绕回HTTP重复上传产生额外整份副本。解析/下载状态独立，ASR仍共享一个串行worker，不增加第二个竞争缓冲的处理器。
- 不把RSS伪装成local_file。增加明确来源描述：feed、节目、单集GUID（可缺）、原始enclosure、实际媒体身份、文字来源/格式、抓取时间及内容hash。GUID只是定位线索，最终按字节/识别配置去重。来源关联表允许同一资产有多种来源，不覆盖已有文件标题、原稿、编辑版本或笔记。
- 节目文字经校验后生成真正的只读文字原稿和稳定块ID；没有音频时回听能力为false。不是伪造一次成功ASR或给文章套假task ID。研究/导出保存实际来源身份，AI产物与原稿分开。
- 运行中取消关闭网络响应、终止该次获取并清理受管暂存、释放预留；已存在的稿件和原媒体不删。下载中断/重启不做半文件续传，明确要求重试；已完成ASR段缓存按既有规则复用。

## R1验收门

- 至少3个真实feed、5个单集；覆盖无全文与至少1个真实text/plain/VTT全文来源。找不到真实全文样本时，该路径只能标记fixture通过，R1不能宣称真实双路径验收齐备。
- 元数据预览期间无单集媒体/全文获取、无模型请求；明确只选一集后才处理这一集。列表截断/时长未知有提示，节目说明不能静默升级成全文。
- 覆盖缺GUID、同GUID不同内容、同内容不同链接、重定向、错误XML、无enclosure、未知时长/超限、无音轨及格式不符；无支持格式时有下一步而非假成功。
- 真实运行：一个音频单集完整本地转写，一个已提供全文单集无需ASR；均完成编辑/手动笔记/导出及重启读回，缺Key可用；AI选段沿用已有能力，至少一条真实选段验证，事先检查现有预算，不绕过上限。
- 下载/校验/排队阶段取消和重启清理分别测试。真实下载并发与文件上传共享额度；5GB不足先清已完成素材，不足暂停，待确认/固定/回听保护保持有效。
- 旧本地文件与私有入口回归，历史原稿/编辑/笔记不被动变更。新增UI人工点验包括中文标题、错误与取消；自动化交互测试不代替点验。
- 最终公开包仍全目录/全字节不含既有禁止的平台字样，无作者路径、数据、凭据、模型或.git；新依赖及第三方许可列入检查。

## 公开README与哈希发布流程（R1完成时同步交付）

公开README标注：本地文件及RSS单集的真实支持边界；章节导读为下一项；跨资料研究为后续候选；已完成/待验收/计划中分别列出。公开版只列通用能力。M2私有排期在内部README和路线记录明确列为“RSS单集与章节导读完成后再评估”，不将被禁止的平台字样写进公开包。

发布清单包含：版本、来源commit、Python/Node及构建工具版本、依赖锁文件摘要、回归与人工验收状态、已知限制、第三方通知、机械扫描结果及复现结果。记录“待外部部署验收”不能写成发布验证通过。

哈希顺序固定：冻结代码/依赖/README → 构建前端 → 白名单打包 → 校验包内manifest的文件集合与逐文件hash → 解压扫描 → 相同输入独立暂存再次构建并比较ZIP字节 → 最后对ZIP生成外部SHA256SUMS.txt和release-metadata.json。ZIP自身哈希不塞回ZIP或其README，避免自引用和哈希循环。任何内容变化都重新打包/校验，不沿用旧校验值。

核验命令在README给出：Get-FileHash <版本ZIP> -Algorithm SHA256，与副文件和可信发布记录比对。补同长度改字节/截断/添入额外文件的失败测试；manifest自列举限制在流程中明确，不能说包内自报哈希等于真实性证明。

SHA256用于完整性比对，不是作者签名。未来若做正式公开发布，另行授权干净历史/公开仓库和签名策略。当前私有仓库保持私有；不能把GitHub自动生成的整仓库source archive当干净核心发行包。只有白名单产物可作为分享候选。
