# 拾文：首版实施计划（2026-10-19）

目标：粘贴单条抖音分享文本，输出忠实讲话全文，只补标点和分段，复制/导出 TXT、Markdown。当前中文、10 分钟以内，目标日常处理 3—5 分钟；首次模型初始化另计。免费优先，月费用超过 ¥10 先汇报。媒体保留策略尚待确认；2026-10-19 用户已明确，“默认保留原视频”是 zcode 误判，并非用户要求。OCR、摘要、改写、自动金句和主页批量后续扩展。

## 采用与取舍

- 采集：只读复用本机 MediaCrawler 的单作品客户端；独立进程、独立浏览器 profile、独立输出。绝不调用其 main.py，不修改配置、日志、台账或定时任务。来源：https://github.com/NanmiCoder/MediaCrawler 。遵循原项目非商用学习许可，保留其源码和归属，不把它重发布为本项目代码。
- 识别：sherpa-onnx + SenseVoice INT8 + Silero VAD 作为轻量本地基线，不先安装整套 CUDA/PyTorch。用现有硅基流动 SenseVoice 做可选对照；API 契约仅文本，不伪造精准词级时间轴。来源：https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html 、https://docs.siliconflow.cn/docs/api/audio-transcriptions-post 。实际效果不达标再考虑 GPU/FunASR/Paraformer，不能用宣传数据替代本机实测。
- 后台：FastAPI + SQLite + 单 worker；持久化任务与分段缓存，模型常驻，有限重试和重启恢复。借鉴 https://github.com/morrisch3n/whisper-scribe 的本地历史和阅读工作区思路；此库成熟度较低且面向文件输入，不直接 fork。
- 网页：遵照 Sites 的本地开发/预览流程，静态 HTML/CSS/JS 与本机 API 同源；不部署成无法直接调用本机浏览器会话的云端空壳。使用 Sites 时不添加不必要云服务。
- 界面：参考 Buzz 的任务/转录工作方式（https://buzzcaptions.com/）；使用 frontend-design 定方向、ui-ux-pro-max 定交互、web-design-guidelines 审查。保留中文可读性、状态真实性和键盘操作，不采用营销页 Hero 或大图。

## 步骤

1. 独立环境和源码目录；只在原浏览器未占用 profile 时复制必要登录资料到新项目，之后只操作新会话。
2. 实测作品 7692043092752338239 获取详情和媒体，探测时长/音轨，保留元数据与来源。
3. 下载官方量化模型并校验可加载；跑完整样本，保存分段、耗时与完整全文。
4. 实现持久化队列、重试、分段恢复、导出、设置与本地原视频回听。
5. 实现网页并完成真实入口端到端验证、375/1440 宽度与失败状态验证。

## 验证

- 样本必须真实获取和转写；不能把分享标题或示例文本当结果。
- 检查原音开头、中间、结尾和数字/人名；未做人工逐字核对时明确范围。
- 验证错误链接、无登录、队列恢复、已完成分段复用、导出与缓存；测试不写入旧项目。
- 安全边界：仅 loopback，同源写请求，禁止任意 URL/任意本地文件读取；密钥不进静态资源、Git 或日志。源码/任务路径隔离。

## 视觉方向

“拾文”是阅读和采集工作区。冷白背景 #F6F8FC、白纸 #FFFFFF、深蓝文字 #17243B、蓝色操作 #2855D9、灰蓝辅文 #59677D、浅边界 #E0E6EF。界面使用系统中文无衬线；正文用易读宋体回退与 1.9 行高，可切换无衬线。左侧窄任务栏，中间原文阅读区，右侧收敛的来源与步骤。圆角只用于控件和工作区外壳，不堆砌统计卡片。空态有明确输入任务，处理状态使用真实阶段和耗时，不造进度百分比。移动端侧栏收起，正文保持完整宽度。尊重 reduced-motion、可见 focus、按钮文字标签。

设计技能数据库两次检索均混入落地页模式；仅采用适配本产品的对比度、功能布局、反馈与无障碍规则，视觉细节按上述中文阅读需求人工决定。
