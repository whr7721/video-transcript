# K1-E0 中文检索评测先行 · 2026-10-24

状态：独立评测实现与本机测量完成，待ZCode审查和用户标注确认。不是生产搜索交付或检索质量验收通过。用户已授权K1开工；R2审查结果未转达，本次没有修改R2业务代码、页面或发布包。

## 做了什么

读取10份真实既有中文资料：6份短稿、2份长中文ASR、2篇文章，合计215个约500字片段、96438个索引字符（含拼接分隔）。原稿以source_uid/version/source_hash/块或段ID/Unicode范围投影，缺时间不造时间。AI导读/整理稿及测试生成的假笔记不混入原始证据。真实个人笔记和编辑版本适配没有在这轮验证。

数据库使用URI mode=ro并持有读取事务，不通过应用store触发初始化或迁移；所有返回片段均回查原文。复跑后冻结语料指纹仍相同。Git只提交代码、自拟题目、位置/指纹、指标，不带原始摘录或用户问题原文。

在首轮排名前冻结30题：两字词、原词短语、同义问法、ASR错字、条件/否定、多词约束各4题，另6题本次文字语料无答案。预分dev/heldout各15；四个ASR意图待听校，全部标签是作者准备的候选，不冒充用户人审金标准。自编题和既有语料存在选择偏差，预分留出不是第三方盲测。

不能因为严格子串对无答案输入返回0条，就说它的拒答更好：它同时漏掉很多正例。BM25产生相关候选也不代表候选含有答案，本轮没有生成答案，不能报告答案幻觉率或拒答准确率。

本机SQLite版本、热查询分位数和每题排名见RESULTS_20261024.json。最终建两个索引约69毫秒，SQLite页面合计2023424字节；留出集双字查询逐题热中位数的P95约0.17毫秒。仅215片段的内存实验，不是生产HTTP速度、冷读或海量语料性能承诺。

标题字段的真实长度为858/795/862/912/781/860/23/29/26/11字符。很多视频标题实际是长分享文案，不能把题名命中当成证据定位。原词literal只是整句输入子串，不能将它包装成最优关键词系统来夸大BM25增益。

## 漏检归因

- trigram四个两字词都不命中，与官方文档一致；双字token索引修复这一类，不需要先用embedding。
- 双字未命中的两个候选正例，一题已标注位置位于Top50第16名，优先核标签/排序；前15条未必完全无用，仍需人工复核。另一题涉及疑似ASR错名，正确名称本身尚需回听，不能凭embedding猜词当纠错。
- 每来源最多2条在本轮未带来命中增益，暂不认为它是必要复杂度。
- 同义问法并未普遍失败；但题集偏向已知资料中的具体概念，不能据此宣布自然语言搜索问题已解决。

## 用户四个真实方向揭示的差距

用户补充的问题保持在runtime/k1/user-queries.json，单独probe，不改冻结题目、不临时调参、不计入30题成绩。query_hash及诊断见USER_PROBES_20261024.json。

1. 幼教方向：Top1是幼儿园求职经历，偏题；其余教育/早期发展材料不能直接作为AI幼教效果证据。本次没有确立直接可靠的对应资料，需补来源或明确不足，语义模型不能凭空补证据。
2. 工具收入方向：存在相关AI内容案例，但没有据此确立实收、付费客户等变现证据；一份可供继续核对的来源在第32名，不可把它算已正确回答。
3. 小型业务发现方向：一份需求发现的相关来源在第17名，属于待逐段标注的潜在相关材料，不自动当金标准。
4. 普通人应用方向：学习/实践闭环的潜在相关来源在第31名，Top5却被其他普通人/AI泛话题挤占。

这几条明确限制了22/24的解释：候选题的定位成绩看起来较好，真实宽泛意图的排序仍不够。不能只挑前一组数字宣布检索可用，也不能将无资料问题归咎于缺向量库。

## 技术路线决定

- 继续用SQLite词法召回作为低成本起点；暂不安装embedding、不建向量库、不将裸BM25接成自动回答。
- 下一步先为这四个方向补人工相关性标注，标出“直接回答/部分相关/仅共词/无答案”，尤其幼教与变现要区分证据范围；保留v1，另立真实意图v2。
- 在固定v2上比较查询要素约束/词法重排与轻量语义重排，先处理Top50里已有相关资料的排序问题。语义重排是待测候选，不是已采用或已证明有效。
- 只有扩大后的题集出现已确认的同义材料无法进入词法候选池，才额外比较语义召回；是否上线由增益、误相关、延迟/资源/费用一起决定。当前数据没有证明需要向量数据库。
- 网站侧下一小步宜先做带原文范围回链的候选列表，标明来源类型与版本、命中原因，不生成无依据结论。真实个人笔记/编辑版本和候选跨块上下文仍需专门验收，不能由本轮10份原稿代表全库。
