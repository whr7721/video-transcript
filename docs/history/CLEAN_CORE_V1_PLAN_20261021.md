# 干净核心 V1：本地音视频入口实施方案（已批准，从 V1-A 开始）

日期：2026-10-21。核对基线：02a1233。用户已确认同学验收环境为Windows 10/11。本轮只读代码与外部资料、形成方案，未开始功能实现，未安装依赖、迁移数据、调用付费模型或改动服务。

## 1. 交付目标与范围

交付一个无需MediaCrawler、抖音登录态或作者电脑目录的本地研究工作台：选择/拖入本地中文音视频 → 本地转写 → 回听/阅读/编辑 → 主动选段研究 → 专题笔记 → 导出。同学在自己的Windows电脑按公开README独立走完一条真实链路，是最终验收线；作者机器上的mock、HTTP200或视频演示不代替独立部署。

V1采用现有React/Tiptap/Radix、FastAPI/SQLite、FFmpeg、SenseVoice INT8 CPU。不替换引擎、不引入GPU/PyTorch/向量库/MCP/任务中间件。中文为验收语种，混合英文不承诺专门质量；英文长内容、RSS、说话人分离、全库问答、Docker和公众托管继续后排。抖音M2在V1之后，原M1审查问题仍独立保留。

建议边界：单文件，每次显式导入一条；单个文件不超过1,000,000,000字节，实际时长不超过7200秒；任务顺序处理。首批支持MP3/M4A/WAV/FLAC/MP4/MOV，必须同时通过容器/音轨/解码检查；扩展名及浏览器MIME仅作提示。不是FFmpeg能读的所有格式都自动对外承诺。

## 2. 源码核对与调研修正

可直接复用：transcribe.py按窗口读取wave、VAD分段、模型加载、语音段指纹缓存；documents版本及原稿、research选段上下文、专题笔记、编辑器、配额状态规则。保留当前模型版本，以隔离入口改造与模型质量变化。

需要改造而非“100%复用”：

- app.py启动直接import batches/discovery/pipeline/session，health依赖MC_PY；公开模式不能只隐藏菜单。
- pipeline.py把抖音解析、下载、FFmpeg、转写和导出串在同一run_task；抽出来源无关媒体阶段，保留私有来源阶段。
- media_buffer.files仅枚举original.mp4/original.part/audio.wav等固定文件；新文件和上传暂存若不接入会漏计占用。mark_evicted仍假定媒体能按链接重新获取，本地来源需改成“重新选择原文件”。
- main.tsx默认存在video_id并生成抖音链接，输入与设置也含平台专属操作。local不能伪造作品ID/URL。
- setup_models.py使用curl.exe及硬编码127.0.0.1:7890代理；start.ps1依赖py启动器且直接运行私有app。它们都是独立部署的实质障碍。
- manuscript.py完整整理稿有24000字上限；旧摘要/金句还有分块数量限制。两小时可转写不代表可以一键全文整理。V1前置显示各功能容量，超限不调用、不截断；长稿仍可完整阅读、编辑、导出及选段研究。
- 短样本CPU约27倍实时是已有测量；“一小时两三分钟”是线性估算。长音频须单独记录机器配置、预处理/识别耗时和内存，模型下载时间另算。

## 3. 入口与交互

公开版默认进入现有工作台，新建按钮改为“导入音视频”。空状态提供“选择文件”按钮和拖放区；点击与键盘选择始终可用，不要求会拖拽。

选中文件后展示：文件名作为可编辑默认标题、大小、支持边界、默认本地识别、缓冲策略，点击“导入并转写”才开始。作者可留空；不要求来源链接。V1不读取用户输入的任意磁盘路径，也不监视文件夹。浏览器把字节传到本机服务，因此会产生受管副本，绝不是零拷贝；源文件不移动、不改名、不删除。

分开显示“传入本机服务 → 校验 → 准备音频 → 排队/识别 → 待确认”，不要用同一个百分比伪装所有阶段。上传用可报告发送进度/取消的浏览器接口；到达100%不代表校验或转写成功。失败给出下一步；上传中断需重选，已完成上传后的ASR失败复用受管副本和段缓存。

结果复用现有原稿/编辑稿/完整整理稿预览和研究笔记。来源面板显示“本地文件”、文件名、时长及回听；没有URL时不渲染“打开抖音”。回听不存在时提示重新导入，而非链接重抓。ASR和时间轴仍诚实标为机器识别、语音段边界。

隐私提示区分两条路径：默认音视频只在本机处理；用户主动AI整理/研究时会发送相应文字，联网研究还会使用搜索服务。不宣称整条AI链完全离线。未配Key也能完成转写、阅读、编辑、手动笔记和导出；研究按钮给配置引导，不因无Key导致启动失败或自动切云端识别。

## 4. 核心分层与抖音剥离

推荐“单份核心实现＋静态注册的私有适配层＋白名单发行包”，不是两个长期分叉仓库，也不只靠VITE开关藏按钮。目录名实施时可调整：

    core/                 通用任务、媒体准备、转写、文稿、研究、笔记、缓冲
    sources/local_file/   上传、校验、文件来源元数据
    private/douyin/      单链接、博主、主题发现、登录与采集依赖
    app_core.py          只装配核心与local来源
    app.py               私有兼容入口，装配核心及显式启用的抖音适配器
    frontend/            共用编辑器，core/private分别组合入口和导航

私有适配器负责URL/作品/登录/下载；拿到受管本地文件后交给同一媒体处理链。核心不得反向import私有适配器。V1只需小型source handler注册与能力声明，不做通用插件市场、动态执行上传插件或引入框架。

前端使用分别可构建的入口/模块组合，而不是静态import所有抖音页再运行时隐藏。公开构建只含core组件和能力，禁用的路由不仅菜单消失，后端也不挂载。打包白名单排除private适配器、extractor/session/batches/discovery专属代码及其私有测试、旧平台首页、内部调研材料、运行数据和登录态。core测试移除私有目录后仍能导入应用和运行；本地文件API始终与现有同源保护一致。

数据方案：私有启动沿用现有data，不重命名任务ID、不移动历史原稿/媒体、不批量回写数据库。core发行包使用自己的空data-core目录；路径由配置/应用根目录决定，不含D盘作者路径。公共任务接口通过source能力分派；读旧任务时在兼容边界把缺失source_kind解释为旧抖音任务，不要求批量迁移。

公开V1产物是可复现生成的干净源码/静态资源包，含公开README和依赖/模型来源说明；V1不把当前私有GitHub仓库改成公开，不附.git历史。后续V3若建公开仓库，从审过的干净包初始化新历史，需单独授权。私有版继续保留所有已实现功能和历史数据。

## 5. 文件数据、去重与缓冲

增加source schema_version=1：kind=local_file、asset_id、display_name、original_filename、sha256、size_bytes、duration_sec、media_type，author/source_url可空。文件名只作为显示文本，不参与受管目录或命令拼接；不要伪造抖音detail结构。公开日志/导出不保存用户原文件绝对路径。

导入过程用随机upload_id暂存，边写边算SHA-256。上传结束才按内容指纹＋识别引擎/模型版本/语言配置去重，数据库唯一约束防并发重复。相同字节改名也复用已有任务；同名不同字节独立。重复导入只丢弃本次临时副本，不覆盖旧原稿/编辑稿/标题/专题笔记。媒体曾清理时，匹配哈希后可补回媒体，但不自动重写已有识别稿。

受管文件采用固定asset名及相对路径清单，ffprobe判定媒体类型，导出仍以任务ID定位。扩展名/MIME不作为安全边界；FFmpeg限制输入容器、协议、音轨选择、超时，拒绝外部引用与播放列表。音轨默认第一条可用音轨，多个音轨明确告知，不默认做说话人分离。

缓冲继续5GB：上传.part、受管源文件、转换临时WAV和完成WAV都计数。通过有锁的上传/转换预留防止并发超卖；计数按实际收到的字节，不信客户端声明。空间不足先清理已确认素材，仍不足则在导入/转换前拦截；保护活动、未确认、固定和回听租约。上传取消/断连/启动恢复只清理本站拥有且失活的暂存，释放预留，不能删外部源文件或活跃任务。

两小时16kHz、单声道、16bit WAV约230.4MB（32000字节/秒），与原文件受管副本一起占缓冲。正常转写完成后仍保留至确认最终稿，之后才进入可清理集合；不默认永久固定。原稿、版本和笔记不属于可清理媒体。

## 6. 独立部署的V1边界

Windows 10/11、Python 3.11 x64、CPU、FFmpeg/ffprobe；不要求RTX、CUDA、MediaCrawler、Chromium或任何抖音工具。公开包附已经构建的前端，普通使用不要求安装Node；开发者构建流程另写。

提供显式环境检查：Python/依赖、FFmpeg/ffprobe、模型3个文件、数据目录权限和端口占用。环境缺失有可操作提示，不把采集器未安装当健康失败。启动入口不会恢复或执行私有采集任务。

模型使用官方固定版本；去掉作者专属强制代理，默认正常网络，代理可选且由用户配置；网络受限可手动放入模型。预设可信文件指纹后再校验，不能把“下载后计算哈希”说成已经验证供应链。V1保留Windows DPAPI保护设置；可沿用环境变量，不迁移成明文Key文件。Docker/Linux密钥存储是后续任务。

README公开版只教core部署与可选Key配置；私有版文档单独保留。发布包附依赖/模型条款来源与第三方通知，先核查复用来源再确定自己代码的许可证，不能通过换LICENSE自动消除历史来源限制。FFmpeg作为外部安装依赖，V1不随包重分发可执行文件。

## 7. 里程碑和验收门

每个实施里程碑单独验证、提交与推送，向用户提供commit区间及ZCode审查请求；P0/P1先处理。2026-10-22 用户批准从 V1-A 开始，以下追加要求纳入各自里程碑，不提前宣布通过。

追加验收：

- V1-A：公开包全目录、全部文件内容与路径机械扫描，大小写不敏感，不能出现 `douyin` 或 `MediaCrawler`。包括隐藏文件、二进制、源码、说明、锁文件和构建资源；最终 ZIP 解压后重扫，禁止仅依赖默认忽略规则的 grep。校验器本身留在内部仓库，不进入公开包。
- V1-B：演示真实长音频导入/转换下的 5GB 配额压力；记录源副本、临时 WAV、完成 WAV、预留及峰值，验证先清已完成素材、不够暂停、未确认/固定/活动/回听租约不被清理。稀疏或合成文件仅可做边界补测，不能代替长素材实演。
- V1-D：在无代理机器实测模型下载一次，记录机器/网络、代理环境及下载器实际行为、下载耗时与可信校验结果；仅清除本机环境变量或 mock 不能代替这一验收。届时若缺独立环境，需要用户协助安排。

| --- | --- | --- |
| V1-A 核心边界与兼容 | 来源模型、通用媒体阶段、core/private装配、配置路径与数据隔离、前端构建边界 | 在复制出的干净目录彻底移除抖音模块/路径，core仍启动；抖音API不注册，界面/构建资源无抖音入口；私有任务历史ID、原稿、编辑版本、笔记和媒体前后清单/哈希不变；旧能力有fixture回归，真实平台访问状态另列 |

长素材测试拆开统计导入、转换、ASR、前端加载、保存与导出；记录峰值内存/磁盘、机器规格及首次模型下载开销，不把短样本估算作速度承诺。禁止用循环同一句话或长静音填充代替真实长播客质量验收，这些只可作为边界fixture。前端大稿应避免每段回调反复全量落库/渲染造成持续退化，按实测节流；浏览器视觉、触屏与中文输入法必须留明确人工记录。

最终放行条件：干净包独立运行＋真实本地链路＋真实长素材＋同学独立部署，四者齐备。若同学尚未实测，状态只能是“待外部部署验收”，不能宣布V1全部通过。

## 8. 后续衔接

V2 RSS仅新增来源适配器与显式单集下载，复用资产/去重/转写/研究，不让RSS逻辑进入ASR核心。M2在私有抖音适配层提交选中资产，沿用原10分钟默认和现有配额；不因local放宽两小时就改变抖音规则。V3再做Docker、跨平台Key、公开仓库/发布；V4处理超长稿分章节整理、跨稿检索、英文与说话人，不把它们塞进文件入口里程碑。

本轮建议结论：确认上述范围后从V1-A开始，先断开依赖和保护历史数据，再接文件入口，最后以同学的独立部署检验“干净核心”是否成立。
