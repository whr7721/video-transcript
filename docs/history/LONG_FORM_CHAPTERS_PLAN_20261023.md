# R2 长稿章节导读实施方案 · 2026-10-23

状态：待用户确认，尚未实施。用户已转达 R1（71f3855）审查通过、无发现。本轮只提交方案与调研决策，不修改功能代码、数据、依赖或调用模型。

## 目标与范围

把“已经能转写两小时，但很难读完”的资料变成可定位、可选择精读的材料：打开长稿 → 看章节目录和短导读 → 阅读原文/回听 → 按需整理一章 → 选段研究、记笔记、导出。

首版覆盖本地文件和 RSS 任务的原始全文，包括有时间的 ASR/VTT 与无时间的节目文字；短稿也可手动使用，不自动花费额度。暂不把文章库、人工编辑稿和已生成整理稿作为分章输入，以免先混入来源版本与编辑语义问题。现有文章入口不受影响。

M2（私有平台选中转写）继续押后；R1、R2 都完成后再评估，不自动启动。跨资料检索、图谱、说话人分离、全自动二创不进入 R2。

## 已核对的现状

- documents.sources 提供 seg-i，但 ID 只有在同一原稿快照内才有意义；不应把它单独当成永久引用。
- manuscript.run 的全文整理上限仍为 24000 字；organizer.source_chunks 是 6000 字/8 块，且单段超长会拒绝。R2 不改这些旧功能限制，新增独立的章节范围处理。
- research.context 目前以选中文字第一次出现的位置建立上下文；重复句可能定位歧义。章节引用必须携带明确来源范围，不能只继续用字符串 find。
- 已有模型请求、每日额度、后台任务、generation、编辑版本、研究笔记和受管媒体均可复用。当前文本模型固定 deepseek-ai/DeepSeek-V4.1-Flash，不另选模型。

## 数据与生成流程

### 1. 原稿快照与可追溯范围

新增独立章节计划与章节产物记录：task_id、source_hash、章节版本、来源类型、模型/提示版本、状态、窗口结果、用量；不回填和重写旧文稿。

引用由原稿 hash + 原始段 ID + 必要的段内字符范围组成。超长单段在派生投影中按句边界切成稳定小片，保留父段及偏移，不修改 ASR/VTT。不得为无时间节目文字补造时间。显示回听仅限媒体实际可用且时间来源有效的情况。

章节按原文顺序构成连续、无重叠的分区；代码验证所有非空正文恰好覆盖一次。字符边界只用于定位，不作为语义分章依据。空白归一规则固定、可逆定位，测试中对照实际原文，不靠字符数相等判断完整。

### 2. 官方目录与无 Key 阅读

RSS 新预览可保留可选章节地址；已有任务不静默联网补资料，用户明确选择才加载。复用 PublicTransport 的受控获取；章节 JSON 初定 1MB、500 条上限，禁用关联图片/网页自动获取。非法、逆序、越界、不同版本等明确报错；官方漏掉的开场/尾声显示补充原文范围，不冒称其为官方命名章节。toc:false 保留其元数据和正文覆盖，通常并入相邻可见范围。

官方时间与文字不是逐词对齐：目录保留原时间；阅读范围采用明确、单调的原稿边界，并披露近似映射。无可靠时间时不能按官方时间强行配文字。

没有目录或 Key，仍能完整阅读，提供明确标为“阅读分段”的本地导航，不叫 AI 章节。官方目录功能若缺真实 feed 样本，必须单独记未实测，不用模拟样例冒充生产支持。

### 3. AI 章节目录与简短导读

显式点击“生成章节导读”才调用。按来源片段组成有界窗口，每窗核心正文最多约 6000 字，附少量前后文用于判断跨窗话题；上下文不重复计入覆盖。模型提出边界、标题、1—3 句导读及支持范围。随后用候选边界和附近原文做一次有界合并检查，消除纯窗口边界造成的假章节；不只给模型摘要再让它臆测全文。

导读回答“这章讨论什么、用了什么例子/条件、适合带着什么问题读”；不追求把每一章包装成正确结论，不强行凑金句。模型边界、引用、输出完整性全部校验，错误结果不发布为完成目录；代码只能保证范围覆盖，语义是否有用另做质量验收。

首版 AI 全稿输入上限建议 60000 字、最多 12 个窗口、一次合并检查（合并输入也设硬上限，超出则显式暂停）；不静默截断。现有 3.1 万和 3.7 万字样本预计约 6—8 次窗口请求，再加 1 次合并，实际以准入预览为准。边界上下文和碎片切分可能增加次数，不能仅用总字数整除估算。

请求开始前显示本次最多调用数、已有缓存、今日剩余额度；沿用现有每日 30 次限制，不自动提高。全部阶段逐次检查共享计数，其他功能消耗额度时允许暂停并保留成果。失败/中断保留已验证窗口；重试只处理未完成窗口，重启后显示可恢复而不自行付费重跑。取消阻止后续调用，已发请求可能仍被计费，不能承诺撤回。

### 4. 按章精读与人工修订

目录直接定位原文不调用模型；“整理这一章”单独触发，输出独立预览，沿用完整整理的保留论据/案例/条件原则和不确定词提示。单章仍限 24000 字，过长先拆章，不偷偷截断。短导读与整理稿分开，不能把摘要拼接称为完整稿。

目录支持改名、在原文位置拆分、合并相邻章节，不支持拖动打乱原文顺序。保存新版本并校验冲突；旧笔记仍指向当时版本，边界改变后相关生成稿标为旧范围，不自动覆盖。缓存键包含原稿 hash、精确范围、模型、提示和处理版本；同内容重试避免重复收费。

章内选段仍接既有解释/案例/核实/专题笔记；服务端验证选段属于对应章节并精确定位，不能错接另一处重复原话。原文引用是证据，AI 整理句不是新的外部证据。支持 Markdown 导出目录、章节产物和来源定位。

## 界面方案

沿用现有工作台：宽屏左侧可折叠目录，中间原文阅读，既有深入面板按需打开；窄屏使用目录抽屉，避免三栏同时挤压正文。阅读正文保持适合中文的行宽、充足行距，采用现有颜色与字体，不新增营销式卡片墙。

目录显示标题、简短导读、可用的真实时间或文字范围；明确区分节目提供、AI 生成、人工修订。首次进入不自动生成；状态区显示已完成窗口/暂停原因/恢复操作。目录点击后定位并清楚标出正文范围，保留阅读位置。焦点可见、键盘可操作、错误可定位、长标题换行；生成失败仍可读完整原文。

### 真实质量评测与通过门槛

1. 复用已有连续两小时中文原稿、R1 的约 79 分钟中文原稿、一个真实长 VTT 全文，共 3 条；英语 VTT 仅验证已有文字的分章，不能宣传英文 ASR。另用无时间纯文本和异常章节夹具检验边界，明确其不是新的真实来源实测。
2. 每条准备头/中/尾及跨窗口候选的检查表，至少 10 个主题/例子/条件定位点。要求范围正确率 100%；至少 8/10 的标题与导读能帮助找到标定内容。无原文支持的实质性新增事实为 0；发现则不以机械覆盖通过替代质量修复。对人是否好用由用户确认，不交模型自评裁决。
3. 从现有上限内同一短稿，固定同模型比较“旧完整整理”和“新按章整理”：预先列出至少 10 个重要信息点（含例子和限制条件），每条产物记录保留/遗漏/新增，不允许关键条件被倒置或捏造。目标信息点保留率至少 90%；若旧方法更好，记录失败并调整，不只展示成功样例。
4. 样本准备和定位尽量由工具完成，用户仅确认边界疑难、导读是否有帮助及重要观点。未人工确认就标为质量待验，不宣布效果通过。
5. 记录每阶段请求次数、实际 token、耗时、缓存命中、失败恢复额外调用；先按实测说明费用，当前不凭模型名字估造人民币单价。现有长期人工/外部环境挂账引用 AGENTS.md，本轮不据此免除新功能验收。
