# K1-P 专题内搜索：批准方案与实施边界

用户批准 K1-E1（77dca9c）无发现，采纳语义层不默认启用、模型留档、既定升级条件。2026-10-25批准本轮生产化方案，按P1/P2/P3实施，各里程碑提交，整体交独立审查。

## 采用与复用

- FastAPI + Python自带SQLite FTS5；中文双字、ASCII词、BM25，复用已评测算法，不导入实验目录或模型。官方机制 https://www.sqlite.org/fts5.html 。索引为派生数据，不修改原稿/编辑稿/笔记。
- Datasette的搜索/片段/来源呈现仅作交互参考，未复制代码或引入服务：https://datasette.io/for/search ，源码查询处理 https://github.com/simonw/datasette/blob/main/datasette/utils/__init__.py 。
- https://github.com/wangfenjin/simple 支持中文拼音，但会增加平台扩展部署，当前无明确收益，不采用。语义/硬约束/词法重排继续按E1结论暂缓，向量库不建。
- UI沿用现有React工作台，依据已读frontend-design/ui-ux-pro-max；技能搜索命中空结果建议和可见焦点。搜索框有可见标签，中文输入法不误提交，结果纯文本高亮，来源聚合；不用自动补全增加首版范围。

## 范围

专题通过research_notes→research_jobs→tasks确定成员。搜索个人理解、已保存选段快照、仍可用的关联原稿全文。来源去重，按全部/个人/选段/原稿筛选。读取全部专题笔记，不沿用最近200条展示限制。

核实后的边界：当前文章库未接入research_topics，不能凭标题把文章自动加入专题。本阶段不新增文章成员管理，不自动扩大至文章库/其他专题/外部引用。AI生成结果不默认索引；来自draft/manuscript的历史选段照实标注。无内容专题保持空态，不造真实笔记。

## 数据与接口

派生表：topic_search_state / topic_search_passages / topic_search_fts。查询事务重新核对成员和原文指纹，变化时原子更新专题索引；错误显示索引不可用，不静默用旧结果。可删除派生表后重建；不引入新依赖。

查询先按专题/类别筛选再取Top50；每页10条。BM25词频统计来自本地派生索引整体，分数不当置信度，也不向用户显示。单个汉字明确用字面匹配回退；标点输入提示。参数作为数据处理。

正文结果携带来源uid、版本、source_hash、原始Unicode范围、文本及高亮。标题匹配单列，不代表正文依据。上下文接口从新快照解析，拒绝过期/移出专题的命中，重复文字不模糊跳转。音轨清理不影响文字，语音段时间非词级精确时间。

## 里程碑与验收

P1：范围投影/可重建索引/查询与上下文接口。验收跨专题隔离、>200条、过滤先于Top50、编辑/成员变化、原文不变、过期引用、Unicode/重复文本、缺来源与错误反馈。

P2：现有专题入口接搜索、分类、聚合结果、原文高亮、相邻上下文、原稿定位/笔记编辑衔接；避免未保存理解丢失。验收中文输入法、旧请求竞态、错误/空结果、分页/返回保留、来源缺失、键盘焦点；GUI验收条件见AGENTS，不以DOM测试冒充点验。

P3：原始评测逐题回归；真实意图逐题报告、paraphrase单列，不把局部关键词匹配当回答充分。开发机1万片段热查询P95目标≤300ms，记录冷建索引与磁盘量；不是已测承诺。无Key离线、公开包全目录检查、确定ZIP与哈希发布流程、README同步。M2/K2未启动，外部验收挂账见AGENTS。
